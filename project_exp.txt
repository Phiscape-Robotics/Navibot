PROJECT BRIEF — NAVIBOT (INITIAL REPOSITORY NOTES)

Confirmed project inputs and repository artifacts
- A Draw.io electronics block diagram and a PNG export are present.
- The diagram depicts a Raspberry Pi 4B, LiDAR, camera, Arduino, L298N dual H-bridge, four DC motors with encoders, an 11.1 V nominal Li-ion battery, and a voltage-regulator/power module.
- The diagram labels UART command/status between the Pi and Arduino, GPIO direction/PWM between the Arduino and motor driver, encoder feedback, and power connections.
- The Python script tools/scan_wifi_devices.py performs best-effort IPv4 device discovery on the connected local Wi-Fi/LAN using host network information, ping, and ARP/neighbour data.
- The project owner confirms two Arduino motor-controller nodes, each controlling two motors, on one shared RS-485 bus connected to the Pi through a UART-to-RS-485 converter.

Current Raspberry Pi design status
- ROS 2 Lyrical Luth on 64-bit Ubuntu 26.04 LTS arm64 is the proposed Pi runtime; verify the actual Pi board and operating system.
- The main design document, Section 6, describes the proposed ROS 2 node architecture, Pi-to-Arduino control flow, candidate binary RS-485 protocol, and safe-state behavior.
- No ROS 2 software has been confirmed as deployed on the physical Pi or validated against the Arduino firmware and hardware. Node IDs 1 and 2, protocol details, motor mapping, and serial settings remain proposals. Do not enable motor output until both Arduino implementations match the protocol and the watchdog/stop behavior is reviewed.

Treat the diagram as a supplied preliminary architecture artifact, not proof of implementation or compatibility. Record design decisions and assumptions explicitly as they are confirmed. Do not infer a clinical, commercial, or other application from the project name alone.
